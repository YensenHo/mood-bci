# 本地固件与 OpenBCI 上位机源码审计（2026-11-19）

## 范围与证据边界

用户解压的资料目录中确有嵌入式源码与上位机源码。本记录基于以下本地文件的只读静态审阅：

- 固件：`RT_BCI_1299_20260907(1)/RT_BCI_1299/RT_BCI_1299/Core/Src/cmd_parser.c`、`ads1299.c`、`readme.txt`。
- 工程目录还包含 `MDK-ARM/stm32f103_eeg08_20251212.hex`、`stm32f103_mpp_eeg08_20251120.hex`、`stm32f103.hex`、`stm32f103.axf` 和 map 文件；文件存在不代表它们与当前板上固件匹配。
- 上位机：`OpenBCI_GUI_serial/.../source/BoardCyton.pde`、`ADS1299SettingsBoard.pde`、`DataProcessing.pde`；中文包中的 `BoardCyton.pde` 也包含相同的阻抗命令模式。
- ADS1299 位定义：TI 官方 [ADS1299 数据手册](https://www.ti.com/lit/ds/symlink/ads1299.pdf)。

**重要限制：**固件解压目录包含大量已修改文件，尤其 `cmd_parser.c`、`ads1299.c` 均与该目录内 Git 的 HEAD 不同；README 将模块写成 ADS1298/STM32F108，而源码、工程文件又指向 ADS1299/STM32F103。它可能是开发版本或被改过的工作副本，不能证明板子当前烧录的固件与它一致。本轮没有编辑、编译或烧录该目录，也没有修改任何接线。

目录内还存在软件版本查询帧（`0xAA...0xBB`）的处理函数，但当前源码把版本答复发往 `USART3`，不是 USB CDC/USART1 数据通道；普通 USB 上位机连接无法据此可靠识别板上版本。若需核对当前镜像，需先确认是否有可用且接线定义明确的 SWD 读取方案，或拿到板上固件版本/烧录记录。

## 结论

### 1. 先前收到的 79 字节不是阻抗结果

当前 `cmd_parser.c` 的串口解析器只处理采样率 `~`、通道配置 `x...X`、开始 `b`、停止 `s`。解析器中没有 `z` 或 `Z` 命令分支。

同一文件还有一个单独的握手逻辑：收到 `0xF0` 后，**下一个字节**到达时调用 `start_BCI()`；该函数固定发出三行 `Success: System is Up` 和两行 `$$$`。所以此前“先发 `0xF0`，随后发 `z`，得到 79 字节启动文字”的结果与固件源码完全吻合：`z` 只是触发握手的后续字节，并未得到阻抗值。此处是对本地源码与旧串口记录的对应解释，仍不能据此认定这份工作副本就是板上固件。

### 2. OpenBCI GUI 的阻抗功能与这份 RT-BCI 固件不匹配

解压的 OpenBCI GUI 源码会先通过 `x...X` 改通道设置，再发送形如 `z<通道><P><N>Z` 的阻抗命令。RT-BCI 当前源码解析器没有实现该命令，因此如果板上运行的是这份源码对应固件，GUI 的阻抗检查不会得到有效的固件阻抗测量。

GUI 的显示算法按信号标准差和 **6 nA** 导联脱落激励电流估算阻抗，并减去 **2.2 kΩ** 串联电阻。这些是 GUI 对特定 OpenBCI Cyton 配置的假设；目前没有资料证明 RT-BCI V1.5 板的激励电流、串联电阻和固件行为相同。即使界面出现数值，也不能把它当成 RT-BCI 的校准阻抗值。

### 3. 这份固件源码的 ADS1299 初始化不等于芯片自检或阻抗检测

- `CONFIG2=0xD0` 设置了内部测试信号源；但活动配置的八个 `CHnSET=0x60` 中 MUX 位为 `000`，选择的是正常电极输入，而不是内部测试输入 `101`。源码中的 `0x55` 测试输入配置被注释掉。因此“测试信号发生器已设置”不代表当前 EEG 输入路径实际采到了内部测试波形。
- `LOFF=0x00`、`LOFF_SENSP=0x00`、`LOFF_SENSN=0x00`：按 TI 数据手册，这份初始化配置没有选择任何正/负输入做 lead-off 检测。ADS1299 芯片有该能力，但不能据此说当前固件已启用。
- `RLD_SENSP=0x00`、`RLD_SENSN=0x00`：没有把通道输入加入 RLD 信号推导。`CONFIG3=0xEC` 的 BIAS buffer 位是 enabled，但零输入选择意味着不能把它解释成已建立有效的电极共模反馈回路。结合用户确认四块板 RLD 都悬空，RLD 未形成有效反馈是当前源码配置的事实；它是否是 25 Hz 污染主因，尚无对照证据。
- `MISC1=0x20` 按 TI 位定义会闭合 SRB1 到各通道反相输入的开关；源码注释把它称为“单端模式”并不准确。它与是否使用共享参考网络有关，但不能单凭寄存器值推断实物 REF 接口走线正确或错误。
- `CHnSET=0x60` 的 MUX=`000` 为正常电极输入，PGA 增益位=`110` 为 24 倍；这是源码初始化值，不是已经从实物芯片读回的寄存器状态。

## 对排查的直接影响

1. 不再用 OpenBCI GUI 的阻抗显示、`z`/`Z` 探测或本地 `capture_impedance.py` 数值判断 RT-BCI 电极接触。只有确认板上固件版本、命令实现、测试电流和校准电阻后，才能恢复阻抗测量流程。
2. 目前最值得做的下一项是**核实当前板上运行固件是否就是这份本地源码**。在此之前，不应改写或烧录。解压目录有未提交改动，任何覆盖、清理或“恢复干净”操作都可能毁掉现有工作。
3. 若后续确认固件匹配，先离体、单板、隔离供电条件下做两项受控验证：a) 以明确的 ADS1299 测试 MUX 读内部校准信号；b) 按 TI lead-off 设计配置状态检测/阻抗功能并验证返回格式。两项必须分开，不能在佩戴状态切换内部测试信号或注入 lead-off 激励。
4. 在 firmware 版本、隔离路径、REF/RLD 网络和上述离体测试通过前，不安排新的长时间佩戴或情绪采集；当前 25 Hz 原始告警仍未解释清楚。
