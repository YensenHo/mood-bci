# 屏幕眼动 + 64 通道脑电 时间同步功能评估报告

> 结论先行：**现有 RT-BCI 板没有可用的硬件触发输入，也没有固件源码；协议帧不含事件通道。**
> 因此「眼动 + 脑电 + 刺激」的**精确共同硬件触发目前无法在不改固件的前提下实现**。
> 本报告已实现**不改固件可做的软件时间同步地基**（记录 + 模拟校验），并把「真硬件触发」所需的厂家问题列清楚。

---

## 一、现有板卡硬件触发是否已确认

**未确认，且资料表明当前不具备。** 结论基于 `RT-BCI产品资料包/` 的原理图与协议原文：

| 项 | 证据（出处） | 结论 |
|---|---|---|
| 外部触发输入 | 两份原理图全文搜 `TRIG/触发/同步/SYNC` 无匹配 | **无标注的触发输入** |
| ADS1299 GPIO1~4 | `RT-BCI-EXP-8CH-V1.0.pdf` 与 `RT-BCI-V1.5.pdf` 均标注 **「GPIO1~4：ADS1299识别ID，高位在前」**（经 10K 电阻上拉 3V3 / 下拉 GND 硬接线编码板卡 ID） | **GPIO 被板卡 ID 占用，非触发** |
| STM32 GPIO | 原理图 PA0~PA15/PB0~PB15/PC13~15 全分配给了 USB、WIFI UART、COM UART、LED、BOOT、SWD、晶振 | 未标注专用触发；未引出引脚≠可用 |
| 通信帧 | `4 通信协议/...WIFI通信协议.docx`：帧 = `0xA0` + 帧计数(1B) + 8ch×3B + 加速度XYZ(6B) + `0xCx` | **无事件/触发字节**；6B 辅助是加速度计 |
| 固件源码 | README 声明「板载固件未上传」；仓库 `find *.c/*.h/*.hex` 无固件 | **无固件源码** |

### 三类判定（资料确认 / 推测可行 / 需厂家验证）

- **资料确认**：ADS1299 GPIO=板卡 ID；帧格式无事件通道；帧计数(byte1)存在；帧尾高半字节 0xC。
- **推测可行（软件层）**：用 byte1 帧计数做**丢帧检测**、用 `time.monotonic()` 做**接收时间基准**、用共同事件（如屏幕亮度变化 + 脑电上对应的伪迹）做**事后软件对齐**。
- **需厂家/实物验证**：是否存在可用的触发输入引脚；固件是否支持事件上传；能否加触发；电气/隔离规格。

### 特别提醒（按用户要求）

- SWD（SWDIO/SWCLK）是调试接口，**不是现成触发输入**；不得当触发用。
- 原理图上未连接的 STM32 引脚，**不代表已引出、固件支持、或可安全接线**。

## 二、不改固件能完成什么（已实现）

在**不依赖眼动仪、不改固件**的前提下，已落地可测试的软件时间同步地基：

1. **统一单调时钟**（`eegscope/sync.py` `SyncTimeline`）：`time.monotonic()`，追加式不可覆盖，眼动/脑电/刺激三类事件在同一时间线上。
2. **脑电帧级记录**（`openbci.py`）：记录 byte1 帧编号 + 接收单调时间 + 估计丢帧数（帧编号跳变，含 256 回绕处理）。
3. **每块板身份 + 统计**（`multiboard.py` `board_stats()`）：4 块板各自的帧统计按物理板序返回。
4. **眼动适配层**（`sources/eye.py`）：抽象 `EyeTrackerSource` + 可注入偏移/漂移/丢帧/无效段的 `SimulatedEyeTracker`，不假定具体设备协议。
5. **刺激事件**（`sync.py` `StimulusScheduler`）：记录计划时间 + 软件记录时间；屏幕实际发光时间标 `screen_onset_known=false`（无外部光电测量）。
6. **落盘**（`recorder.py`）：会话额外写 `sync.json`（时间线 + 每板帧统计快照 + clock_note），`session.npz`/EDF/CSV 原样保留。

### 诚实边界（已在代码注释与 clock_note 里写明）

- 记录的是**电脑接收时间**，不是设备精确采样时间；设备采样时间见 `sample_counter`/`device_ts` 字段。
- 掉线补零/截断的数据**不会被当成真实连续样本**（丢帧单独记在 `n_dropped_est`，不填充进信号）。

## 三、真硬件共同触发需厂家回答的问题

若要做「屏幕刺激 → 眼动 + 脑电」的**精确共同硬件触发**（微秒~毫秒级），需向厂家确认：

1. **可用触发输入**：板上有无未占用、且已引出到接口的 GPIO/专用触发脚？电平和极性？
2. **固件源码**：能否提供 STM32 固件源码或触发注入 API？（现无源码，无法改固件加事件编码）
3. **事件编码**：固件能否在数据流里插入事件标记（如占用某个字节/辅助字节），或提供中断/事件引脚？
4. **隔离与电气规格**：触发源（屏幕光电传感器/TTL）与电极回路的电气隔离方案、共地、电平兼容、最大电压——涉及人体时**必须先离体测试、确认隔离**，不得把电脑地/触发源直接接到电极、REF 或 RLD。
