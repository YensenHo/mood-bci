# ST-LINK v2 烧录 RT-BCI 固件指南（2026-11-21 修订版）

> 目标：把改了 RLD 的固件烧进 4 块 RT-BCI 板（STM32F103C8），根治 50Hz 共模。
> 工具：DZQJ ST-LINK v2（国产克隆，用开源 stlink-tools 最稳）。

## ⚠️ 核心结论（先看这个）

**烧的是二进制补丁固件，不是 GCC 重编译固件！**

- ❌ `build_gcc/stm32f103_rld.bin`（GCC 重编译，31KB）→ **上板卡死**（握手无响应，已实锤）
- ✅ `build_rld_patched_123.bin`（板 1/2/3，基于原厂固件 7c07feca + RLD 字节）
- ✅ `build_rld_patched_4.bin`（板 4，基于原厂固件 cf009f27 + RLD 字节）

补丁固件是 64KB 完整 flash 镜像，基于**原厂能跑的固件**只改 3 处 RLD 字节：
`0x394` CONFIG3 `0xEC→0x4C`、`0x3AE` RLD_SENSP/N `movs r0,#0x00→#0xFF`、
`0x3B4` LOFF 复位 `strb→movs r0,#0x00`。

## 1. SWD 接线（3 根线就够）

| ST-LINK v2 引脚 | RT-BCI 板 | 说明 |
|---|---|---|
| SWDIO | SWDIO 焊盘 | PA13 |
| SWCLK | SWCLK 焊盘 | PA14 |
| GND | GND | **必须接**（共地） |
| 3V3 | — | **可不接**（板子 USB 供电，3V3 只做电压参考） |

板子上电再烧（USB 供电或电池）。

## 2. 识别板 4（固件批次不同）

4 块板中 3 块固件相同（`7c07feca`），1 块不同（`cf009f27`，含 `"1299_v1.0"` 字符串）。
烧录前读回 flash 尾部（0x7C00+，USB 描述符区）判断：

```bash
st-flash read /tmp/check.bin 0x08000000 0x10000
python3 -c "
cur=open('/tmp/check.bin','rb').read()
b4=open('backup/board4_original.bin','rb').read()
d=sum(1 for i in range(0x7C00,0x10000) if cur[i]!=b4[i])
print('board4 型' if d==0 else 'board1/2/3 型')
"
```

## 3. 烧录流程

```bash
cd ~/mood_BCI/firmware
# 板1/2/3：
st-flash write build_rld_patched_123.bin 0x08000000
# 板4：
st-flash write build_rld_patched_4.bin 0x08000000
```

## 4. 关键坑：烧完必须冷启动！

软件复位（`st-flash reset`，AIRCR）**不够**，烧完后必须**拔 USB 数据线重插**（或蓝键关机再开机），
否则发 `b` 命令不流数据（0 字节）。

## 5. 验证：发 'b' 命令测流数据（不是看 $$$ 握手）

**握手协议坑**：固件 `order_data_parse` 的 `if (last_byte == 0xF0)` 逻辑，单发 `0xF0` 不触发
`start_BCI()`（不返回 `$$$`）。**真正开始采集的命令是 `b`**。

```bash
cd ~/mood_BCI/software && env -i HOME=$HOME PATH=/usr/bin:/bin:/usr/sbin:/sbin:/opt/homebrew/bin PYTHONPATH= .venv/bin/python -c "
import serial, time
ser = serial.Serial('/dev/cu.usbmodemXXX', 115200, timeout=0.3)
ser.dtr=True; ser.rts=True
time.sleep(0.5)
ser.write(b'b')  # 开始采集
time.sleep(0.6)
buf=b''
while time.time() < 3.0:
    d = ser.read(4096)
    if d: buf += d
print(f'{len(buf)} 字节, {buf.count(bytes([0xA0]))} 帧')
ser.close()
"
```

## 6. RLD 生效判据

烧录补丁固件后，通道**没接 RLD 电极时会打满**（RMS ~132k µV、peak 满量程 187485 µV）——
这是 RLD 开启但反馈回路开路（A2 悬空）的**正常现象**，证明 RLD 修复生效了。

接好 RLD 电极（A2）+ 参考（A1）后，通道恢复正常，戴帽测闭眼 α 看 50Hz 是否降下来。

## 回退

```bash
st-flash write backup/boardN_original.bin 0x08000000  # 刷回原厂固件
```
