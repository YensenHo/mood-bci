# RLD 修复固件烧录 · 经验教训复盘（2026-11-21）

> 一句话：4 块 RT-BCI 板的 50Hz 工频污染已根治（~150k → ~714 µV²/Hz，约 210 倍），
> 数据质量达到可做情绪分析的水平。代价是踩了一串烧录的坑，全部记录在此。

## 一、成果（数字说话）

| 指标 | RLD 关闭（修复前） | RLD 开启（修复后） |
|---|---|---|
| 50Hz 工频 | ~150,000 µV²/Hz（淹没一切） | **713.7 µV²/Hz** |
| 25Hz 板载 | 高 | 868.2 µV²/Hz |
| α 频段功率（64 通道均值） | 被 50Hz 盖住 | 24,032 µV² |
| α 信号 / 50Hz | — | **34 倍** |
| 通道质量 | — | 61/64 OK（0 平线、3 打满） |

**结论：能分析情绪。** α/θ 频段干净，50Hz 不再淹没信号。

## 二、烧录踩的坑（按踩坑顺序）

### 坑 1：烧错固件（最致命）
- ❌ `build_gcc/stm32f103_rld.bin`（GCC 重编译，31KB）→ 上板卡死，握手 0 响应
- ✅ `build_rld_patched_123.bin` / `build_rld_patched_4.bin`（64KB 二进制补丁，基于原厂固件只改 3 个 RLD 字节）
- **根因**：GCC clean rebuild 改变了中断向量表/代码布局，STM32 上板行为完全不同。小改动**优先二进制补丁**，不是重编译。

### 坑 2：误判「握手失败」
- 现象：发 `0xF0` 等 `$$$` 无响应，误以为板子卡死
- **真相**：固件 `order_data_parse` 的 `if(last_byte==0xF0)` 逻辑，**单发 `0xF0` 不触发** `start_BCI()`；真正开始采集的命令是 **`b`**
- 判据修正：看「发 `b` 后能否读到 `0xA0` 帧」，不是 `$$$` 握手

### 坑 3：烧完必须冷启动
- 现象：烧录后软件复位（`st-flash reset`）发 `b` 0 字节，以为固件坏了
- **真相**：AIRCR 软件复位只复位 CPU，ADS1299 等外设电源状态没复位；**拔 USB 断电重插**（或蓝键关机再开机）才真正冷启动
- 实测：软件复位后 0 字节 → 冷启动后 840 帧

### 坑 4：板 4 是不同批次
- 4 块板中 3 块固件相同（`7c07feca`），1 块不同（`cf009f27`，含 `"1299_v1.0"` 字符串）
- 识别方法：读回 flash 尾部（0x7C00+ USB 描述符区）对比，差异 0 字节 = board4 型
- 板 4 必须用 `build_rld_patched_4.bin`（基于它自己的原厂固件）

### 坑 5：ST-Link 接线
- GND **必须接**（共地），3V3 **可不接**（板子 USB 供电，3V3 只做电压参考，接了反而可能冲突）

### 坑 6：无供电集线器带不动 4 板
- 4 块板同时持续流数据（>8 秒）会随机掉线（板 4 尤甚），导致频谱脚本 `concatenate` 报空
- detect_boards 逐块测能成功，diag_spectrum 4 板同时读会超时
- **解决**：换有供电集线器，或逐板测 / 缩短采集时长

## 三、两个小尾巴（软件侧已处理）

1. **50Hz 残留 14.8%（占 α 均值）**：`eegscope/dsp.py` 已有 50Hz + 25Hz 陷波（`iirnotch` Q=30，深度约 −50dB），能把 714 µV²/Hz 压到 <1，信号链是「带通 0.5–45Hz + 双陷波 + 去直流」
2. **3 个打满通道**：`quality.py`（`railed_rms`）+ `diagnostics.py`（打满/平线判定）+ `analyze_session.py`（`excluded_channels`）已自动剔除坏通道，不参与指标统计

## 四、遗留项

- 有供电集线器（替换无供电的，避免 4 板同时读掉线）
- 若要看明显的闭眼 α 增强，电极需确认贴到枕区 Oz（当前戴帽 α 睁闭眼差异小，是电极位置问题，非 RLD 问题）
